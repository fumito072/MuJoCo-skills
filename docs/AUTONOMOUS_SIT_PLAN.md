## 2. アーキテクチャ: 1モデル + FSM(50 Hz)

学習済みモデルは**歩行1個だけ**。着座はスクリプト降下で、両者を有限状態機械で接続する。

```
NAVIGATE ──dist<0.6m──▶ ALIGN ──err<5.5cm & |yaw|<25° (0.5s保持)──▶ SETTLE
   ▲                      ▲                                          │
   │                      └────────リトライ(最大3回)←──────────────┤ ドリフト/ヨー検査
   │                                                                 ▼ 両足接地+静穏ゲート
 VFH 21レイ                                                       FREEZE(ONNX切断)
 (group 4 マスク)                                                    │ キーフレーム立位へ
                                                                     │ 0.4sランプ→安定まで
                                                                     │ ポーリング(≤3s)
                                                                     ▼ 静的安定を検証
                                                                    SIT(1.0s降下)──▶ HOLD(3s)
```

- **NAVIGATE**: 公式 29DOF joystick ONNX(`models/policies/g1_joystick_29dof.onnx`)を
  レイキャスト VFH(21本, 200° FOV, 障害物 geom group 4 のみにマスク)で操舵。
- **ALIGN**: 同じ ONNX に体座標系 P サーボ(位置 + **ヨー** wz=clip(−1.2·yaw, ±0.5))。
  目標はノミナル・ドック点 = 座面中心 + 8 cm 前方(バスン実測の基準点)。
- **SETTLE**: 校正済みトリム(vx −0.20, vy +0.07)で足踏み静止 → ドリフト/ヨー検査 →
  **両足接地かつ横揺れ静穏**の瞬間を待つ。
- **FREEZE**: ONNX を切り、d.ctrl をキーフレーム立位へ 0.4 s でランプ → 静的安定
  (両足接地, |v|<0.10 m/s, |roll|<3°, |pitch|<10°, バスン内)を**満たすまで**ポーリング。
  これで降下の初期条件が検証済みスクリプト着座と**完全に同一**になる。失敗時は ONNX を
  コールドスタート条件(phase=[0,π], last_action=0)で再投入し SETTLE からリトライ。
- **SIT/HOLD**: 検証済み着座姿勢(hip_pitch −1.254, knee +1.611, ankle_pitch **+0.137**
  = 意図的な底屈バイアス)へ 1.0 s 線形ランプ → 3 s 保持。

## 3. E2E で発見・修正した失敗モード(全3回の試行)

統合は「部品が動けば繋がる」ものではなかった。E2E でのみ露出したバグ:

1. **ヨー無制御**(試行1): ドッキング 2.5 cm でもヨー +64° で降下 → 前方転倒。
   VFH の迂回方位がそのまま残り、ALIGN 中もヨーが漂流(+36→+64°)。
   → ALIGN にヨーサーボ + 全ゲートにヨー条件(±25° / ハード予算 ±45°)。
2. **足踏み中の直接降下**(試行2): ドッキング 1.0 cm / ヨー 17° でも、降下開始 0.4 s で
   ロール暴走(−1°→+24°→+86°)、横に 0.8 m 滑落。原因 = 検証済み着座は**静的対称立位**
   開始なのに、非対称な歩容相から対称着座目標へ直接ランプしていた。
   → FREEZE 状態を新設(上記)。
3. **固定時間の安定判定 + 乱れた状態での再投入**(試行3): 切替の残留横揺れは減衰振動で、
   固定 1.0 s 後の判定は振動の山に当たり得る。さらに不安定なまま ONNX+位置サーボを
   再投入して転倒。→ 安定判定を「満たすまでポーリング」化、リトライはトリム足踏み
   (SETTLE)経由で回復させてから再ドッキング。
4. **ドック点のずれ**(試行1-2に内在): 座面中心へのドッキングはノミナルから −8 cm
   (唯一の脆弱方向 −x)に相当 → ドック点を座面中心+8cm 前方に修正。

## 4. 土台となる実測ファクト(個別に検証済み)

- **スクリプト着座**(`training/g1_sit_scripted.py`): キーフレーム立位から 1.0 s 降下で
  pelvis_z 0.5549 / 座面荷重 163 N。鍵は ankle kp=20(hip/knee 75 の 1/4)対策の底屈バイアス。
  ≥1.5 s の遅い降下は全て前方転倒(敵対的検証済み: 重力・質量・拘束の改変無し)。
- **着座バスン**: xy 全方向 ±8 cm OK(±5 cm 品質完璧)、唯一 −x 方向のみ −9 cm OK /
  −11 cm 転倒。ヨー ±45° 全 OK。
- **29DOF 歩行 ONNX**(`training/g1_walk_onnx.py`): obs 103次元レシピ + ゼロ指令トリム
  (vx −0.20, vy +0.07)で足踏みドリフト 2.09 cm/s。**位相凍結は2秒で転倒**(ONNX を
  動かしたまま止める手段は無い → FREEZE では ONNX 自体を切る)。
- **VFH ナビ**(`.agents/skills/mujoco-obstacle-navigation`): mj_ray 21本を group 4 に
  マスク。本統合ではセクタ拡幅を ±2→±3 に(骨盤ボックス外接半径 0.14 m がクリアランス
  0.07 m で掠ったため)。
- **シーン**: playground FEET_ONLY_FLAT_TERRAIN + g1_sit_env の椅子(座面高 0.45 m)+
  障害物3個。**正直な注記**: この G1 モデルの足は床と明示 pair でのみ衝突し、脛/腿には
  衝突ジオメトリが無い → 障害物回避の物理的強制は骨盤ボックスのみで、回避の保証は
  VFH + クリアランス計測による。

## 5. 今後のトラック(優先度順)

### A. 堅牢化(RL は必須ではなく強化)
現状は決定論的な1シナリオの成功。次の堅牢性が未検証:
- 障害物配置・椅子位置のランダム化での成功率測定(N=50 スイープ)
- ドッキング失敗→リトライ経路の実地カバレッジ(今回は1回も使われずに成功)
- RL 着座ポリシー(xy オフセット±10cm ランダム化、先行研究: 2段階 sit / InterPhys 流の
  椅子ランダム化+単純報酬)— 学習は Kaggle(電話認証待ち)/ Lightning.ai / または
  **Mac ローカル CPU-PPO**(実測 33,282 ctrl-steps/s 集計 → 20M ステップ≈15分の物理、
  現実的)。推論は常に Mac ローカル。

### B. 知覚の自律化
現在の VFH は障害物 geom group を知っている(特権情報)。次段:
- 深度カメラレンダリング(MuJoCo offscreen)→ 擬似 LiDAR 化 → 同じ VFH へ
- 椅子位置も検出に置換(現在は既知座標)

### C. VLA 統合(最終形)
「椅子に座って」→ VLM がシーン理解 → 目標座標+タスク列を FSM に発行。
FSM はそのまま低レベル実行器として再利用できる(Chao 2019 の階層構成と同型)。
Mac 128GB はローカル VLM(MLX)に十分。
