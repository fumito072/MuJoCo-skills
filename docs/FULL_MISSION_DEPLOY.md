## 0. ゴールと到達点

ミッション: 部屋の反対側から、**障害物を自ら検知・回避**して実在の椅子
(3階講堂遠隔操作席)の前まで歩き、**0.22m のフットレスト台に登り**、**着座**する。
全てシミュレーション内で連続1ロールアウト、Mac ローカル(GPU/クラウド不要)。

実行:

```bash
.venv-rl/bin/python training/g1_full_mission.py          # フルミッション(GIF付き)
G1FM_NOGIF=1 .venv-rl/bin/python training/g1_full_mission.py   # 高速判定
```

アーキテクチャの核心: **シムで検証されるコード=実機に載せるコード**。
ミッション制御は `deploy/g1_mission_controller.py`(numpy+onnxruntime のみ、
MuJoCo 非依存)に実装され、`training/g1_full_mission.py` はそれを MuJoCo に
接続する薄いアダプタ。実機側アダプタ(`deploy/run_on_robot.py`)は同じ
コントローラに実センサを繋ぐだけ。

```
                 ┌─ training/g1_full_mission.py(シム・アダプタ)── MuJoCo 物理
state dict ──▶ deploy/g1_mission_controller.py ──▶ target/kp/kd
                 └─ deploy/run_on_robot.py(実機アダプタ)──── unitree_sdk2py
```

## 1. ミッション FSM

```
NAVIGATE(歩行ONNX+VFH障害物回避、ゴール=台手前1.25m)
  → TURN(床上で180°回頭 — 台上では回頭不能のため先に向きを作る)
  → BACKUP(PI ステーションキーピングで後ろ向きに台際 y0.67 へドッキング)
  → CLIMB(★RL方策: 後ろ向き段差登り、SITモード剛性ゲイン kp300)
  → SIT(検証済み剛性降下レシピ: 立位0.4s→降下0.6s→静定0.8s→姿勢1.5s→保持3s)
```

各部品の出自: 歩行=公式 playground 29DOF ONNX(無改変)/ VFH=既存スキルの実証済み
パラメータ / BACKUP の PI サーボと着座レシピ=実測検証済み(docs/AUTONOMOUS_SIT_PLAN.md
v3)/ **CLIMB=本フェーズで新規にRL学習**(§3)。

## 2. なぜ「後ろ向きに登る」のか(設計判断)

- 座るには台上で「背を椅子に向けて」立つ必要があるが、**台は0.6×0.3mで歩行・
  回頭は不可能**(実測: 歩行方策のコールドスタートだけで台から落ちる)
- 前向きに登ると台上で180°ピボットが必要になる → 詰み
- **床で回頭してから後ろ向きに登れば、台上での向き変えが一切不要**
- 後ろ向きステップは人間の手作業振付では困難だが(§3)、RLには前後の区別は
  単なる座標の符号 — 学習にとって難度は同じ

## 3. Phase 3: 段差登り — スクリプト14連敗 → RL

### 3.1 スクリプト方式の敗北記録(全て実測、教材として保存)

剛性ゲイン+ウェイポイント振付+足首/股関節の CoM-PD フィードバックまで投入して
14回失敗。本質的な敗因は3つの連成:

1. **遊脚質量の反作用**: 脚(~5kg)を振ると CoM が逆方向へ逃げ、片脚支持の
   支持多角形(足1枚=±3cm)を即座に割る
2. **ベース後退**: CoM を支持足上に保つ制御は、脚を前に出すと**胴体を後ろに
   下げて釣り合わせる**(物理的必然)→ 着地点が届かない
3. **横ロールの蓄積**: 片脚支持の1-2秒間に足首・股のフィードバック権限
   (足首ロール±0.26rad、CoP=足幅)が飽和する

→ 結論: 0.22m 段差の片脚支持遷移は**閉ループ全身協調**が必要 = RL の出番。
(g1-isu が全タスク一括RLで3.5Mステップ未習得だったのに対し、本実装は
**登りだけを切り出した専用タスク+密な報酬**で学習)

### 3.2 RL タスク設計(training/g1_climb_env.py)

- 行動: 脚12関節の位置目標(50Hz、±0.45rad、kp300/kd8)
- 観測52次元: 重力・ジャイロ・体速度・基準高・ヨー誤差・**目標点への体座標
  ベクトル**(実機では椅子測量+オドメトリ)・脚関節位置/速度・足接触・前回行動
- 報酬: ポテンシャル形(目標点+台上高への前進)+台上足接触+微小生存
  −姿勢/ヨー/行動レート/関節速度ペナルティ、成功+100/転倒−20
- **チェーン接続を見据えた初期化ランダム化**: 本プロジェクト最大の教訓
  (歩行マーチからの引き継ぎ過渡が全てを壊す)を環境に焼き込み — スポーンに
  基準速度±0.15m/s・関節速度±1rad/s・関節角±0.12radのノイズ
- **報酬ハッキングと対策**(実際に起きた): 初回学習は「段差の縁に腰掛けて
  生存ボーナスを満額回収する」局所解に収束。対策=生存ボーナス1/5+
  **足以外の身体と椅子の接触にペナルティ**+高さ項強化
- 学習: SB3 PPO、M5 Max CPU 10並列 **~9,000 steps/s**(クラウド不要)

### 3.3 結果(正直な現状: 部分達成)

**36Mステップ・6回の報酬/カリキュラム手術の結果**:
- 近接逆カリキュラム(RSI)領域からの成功率 **35-45%**(成功+200の価値は学習済み)
- 段の縁への「つま先掛け片足ホールド」を自力発見し無期限維持(登りの~70%)
- **床スポーンからの完全登攀は 0/20 — 未達**。つま先掛け→深い足設置→第二足移行の
  価値伝播が3つのカリキュラム設計でも床まで届かなかった
- フルミッションは転倒ゼロで CLIMB タイムアウトまで進行(assets/g1_full_mission.gif
  =現状フロンティアの記録: 回避0.186m→回頭→後退ドッキング→登り試行→ホールド)

**スクリプト側の収穫**: 25回の試行から**検証済みプリミティブ「縁着座」**を獲得
(後ろ向き剛性降下で台の縁に安定着座、base z 0.375/pitch 0° —
training/g1_edge_sit_probe.py)。台上で座位から足を置く空間が無いことも幾何学的に確定。

**次の登攀候補(優先順)**:
1. RSIカリキュラムの**適応的後退**(成功率連動で状態バンクを床側へ自動シフト)+
   GPU学習(MJX/Isaac で 10^8 ステップ級 — CPUの10倍速)
2. **肘掛け手押しスクート**: 縁着座から手で肘掛けを押して体を持ち上げ深部へ
   (hand_collision×椅子ペア追加+腕振付。人間と同じ手順)
3. ホールド→橋状態を繋ぐ**第二方策**(2方策チェーン)

## 4. 正直な注記(シムの妥協点)

| 項目 | 状態 |
|---|---|
| 障害物回避の物理 | VFH+骨盤ボックスのみ(脚は障害物を貫通可能 — クリアランス計測で担保) |
| 椅子・自己位置 | 既知座標(特権)。実機は測量+オドメトリ、知覚化は次トラック |
| クッション | 剛体近似(実物は沈む=実効座面が低い → シムが保守側) |
| センサ | 理想(ノイズ・遅延なし)→ 実機チェックリスト対象 |
| CLIMB方策 | 学習分布(スポーン±4cm/±0.10rad+速度ノイズ)外の状況は未保証 |

## 5. 実機 Linux への展開(deploy/)

`deploy/README_DEPLOY.md` が正典。要点:

1. **バンドル**: コントローラ+config.json+ONNX2個(歩行/登り)。
   ロボット側依存は `numpy onnxruntime unitree_sdk2py` のみ(torch不要 —
   `export_climb_onnx.py` が正規化込みでONNX化)
2. **アダプタ**: `run_on_robot.py` は 500Hz lowcmd ループ+50Hz 判断+線形補間の
   unitree_rl_gym 慣行構造。**TODO(HW) 6箇所**(SDK配線・関節マップ・推定器・
   椅子フレーム自己位置・LiDAR整形・E-stop)は現地でしか書けない/検証できない
3. **段階投入**: ゲイン校正(吊り)→ SIT単体 → CLIMB単体(モック段差)→
   歩行系 → フルチェーン。各段階ハーネス+E-stop
4. **「ぶち込むだけ」の正確な意味**: 制御ロジック・方策・校正値はシム検証済みの
   まま持ち込める。現地作業は上記アダプタ配線と安全検証であり、
   **制御設計のやり直しは発生しない**(それがこの構造の価値)
